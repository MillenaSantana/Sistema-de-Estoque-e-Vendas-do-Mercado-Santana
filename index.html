Dicionário de Dados do Mercado Santana

1. Modelo conceitual

Este modelo representa o controle de vendas e estoque do Mercado Santana. A proposta é organizar o cadastro dos produtos, registrar as vendas e acompanhar as movimentações do estoque, facilitando a identificação de produtos que precisam ser repostos.

EntidadeRelaciona-se comCardinalidade
CATEGORIAPRODUTO1:N — uma categoria pode possuir vários produtos; cada produto pertence a uma categoria.
VENDAITEM_VENDA1:N — uma venda pode possuir vários itens; cada item pertence a uma venda.
PRODUTOITEM_VENDA1:N — um produto pode aparecer em vários itens de venda.
PRODUTOMOVIMENTACAO_ESTOQUE1:N — um produto pode possuir várias movimentações de estoque.

Produto representa os produtos comercializados pelo mercado.

Categoria organiza os produtos por grupos, como alimentos, bebidas, limpeza e itens domésticos.

Venda representa uma venda realizada pelo mercado.

Item_Venda registra os produtos e suas quantidades dentro de cada venda.

Movimentacao_Estoque registra alterações na quantidade dos produtos em estoque.

2. Fluxo de dados

Produto cadastrado → venda realizada → itens da venda registrados → estoque atualizado → consulta do estoque atual → verificação do estoque mínimo → identificação da necessidade de reposição.

3. Convenções do dicionário

O dicionário apresenta os atributos de cada entidade, seu tipo de informação, obrigatoriedade e finalidade no sistema.

TermoSignificado
PKChave Primária — identifica de forma única um registro.
FKChave Estrangeira — relaciona uma entidade com outra.
ObrigatórioCampo que deve ser preenchido no cadastro ou registro.
Atributo de domínioCampo que possui opções ou valores previamente definidos.
Atributo derivadoValor obtido a partir de outros dados, como subtotal e valor total.

4. Dicionário de dados por entidade

PRODUTO

PRODUTO = @id_produto + nome + preco_venda + quantidade_estoque + estoque_minimo + status + id_categoria

Leitura: id_produto identifica cada produto de forma única. id_categoria relaciona o produto à sua categoria.

AtributoTipo físicoObrigatórioSignificado e relevância
id_produtointegerSim (PK)Identifica unicamente o produto no sistema.
nomevarchar(120)SimNome utilizado para identificar o produto.
preco_vendadecimal(10,2)SimValor pelo qual o produto é comercializado.
quantidade_estoqueintegerSimQuantidade disponível do produto. Não pode ser negativa.
estoque_minimointegerSimQuantidade mínima usada para identificar a necessidade de reposição.
statusvarchar(20)SimSituação do produto, como disponível, vencido ou danificado.
id_categoriaintegerSim (FK)Identifica a categoria à qual o produto pertence.

CATEGORIA

CATEGORIA = @id_categoria + nome

Leitura: id_categoria identifica cada categoria e nome descreve o grupo de produtos.

AtributoTipo físicoObrigatórioSignificado e relevância
id_categoriaintegerSim (PK)Identifica unicamente a categoria.
nomevarchar(80)SimNome da categoria, como alimentos, bebidas, limpeza ou itens domésticos.

VENDA

VENDA = @id_venda + data_hora + forma_pagamento

Leitura: id_venda identifica a venda; os demais atributos registram quando ocorreu, seu valor e a forma de pagamento.

AtributoTipo físicoObrigatórioSignificado e relevância
id_vendaintegerSim (PK)Identifica unicamente cada venda.
data_horadatetimeSimRegistra a data e o horário da venda.
forma_pagamentovarchar(6)SimForma utilizada para realizar o pagamento.

ITEM_VENDA

ITEM_VENDA = @id_venda + @id_produto + quantidade + preco_unitario + subtotal

Leitura: id_venda e id_produto identificam o item dentro da venda. A entidade permite registrar vários produtos em uma mesma venda.

AtributoTipo físicoObrigatórioSignificado e relevância
id_vendaintegerSim (FK)Identifica a venda à qual o item pertence.
id_produtointegerSim (FK)Identifica o produto vendido.
quantidadeintegerSimQuantidade do produto incluída na venda.
preco_unitariodecimal(10,2)SimPreço de uma unidade do produto no momento da venda, preservando o histórico.
subtotaldecimal(10,2)SimValor do item, calculado pela quantidade multiplicada pelo preço unitário.

MOVIMENTACAO_ESTOQUE

MOVIMENTACAO_ESTOQUE = @id_movimentacao + id_produto + tipo + quantidade + data_hora + motivo

Leitura: cada movimentação é identificada por id_movimentacao e está relacionada a um produto.

AtributoTipo físicoObrigatórioSignificado e relevância
id_movimentacaointegerSim (PK)Identifica unicamente a movimentação de estoque.
id_produtointegerSim (FK)Identifica o produto que sofreu a movimentação.
tipovarchar(10)SimIndica se a movimentação representa uma entrada ou uma saída.
quantidadeintegerSimQuantidade de produtos movimentada.
data_horadatetimeSimData e horário em que a movimentação ocorreu.
motivovarchar(30)SimMotivo da movimentação, como venda, vencimento ou dano.

5. Restrições e regras aplicadas ao modelo

  • Cada produto deve possuir um identificador único.
  • O estoque não pode assumir valores negativos.
  • Uma venda reduz a quantidade disponível do produto.
  • A quantidade vendida não pode ser maior que a quantidade disponível.
  • Cada produto possui um estoque mínimo para auxiliar na reposição.
  • Produtos vencidos ou danificados não podem ser comercializados.
  • As vendas e movimentações de estoque permanecem registradas para consulta e histórico.
